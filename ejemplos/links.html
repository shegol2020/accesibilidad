1. Screen Reader Behavior

The real link will be read as a “visited link” if the URL has been visited before. Screen readers rely on the native HTML <a> element and the browser’s visited‑state.

The custom link (<div role="link">) will be read simply as “link”, but never as “visited”, because:

  • It has no href
  • Browsers do not apply the :visited state to non‑link elements
  • Screen readers only announce visited‑state for real HTML anchors

2. Is This a WCAG Violation?

You asked whether the lack of “visited” state is an accessibility violation. I explained that:

No, this is not a WCAG violation.

WCAG does not require:

  • that visited links be visually distinguished
  • that screen readers announce visited‑state
  • that custom ARIA links mimic the full behavior of real <a> elements
